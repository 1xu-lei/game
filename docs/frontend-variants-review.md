# 前端三版本设计评审说明（A / B / C）

> 目的：让主人在 3 分钟内看完三套方案并挑一套。
> 三个版本**共用**同一份设计 token、同一个 store、同一个预览引擎，只更换信息架构与视觉组织，所以选版 = 选「信息怎么排」，不是选「功能有没有」。

---

## 1. 三版对照

| 维度 | A · 雨夜指挥台 | B · 沉浸全景 | C · 水文仪 |
|---|---|---|---|
| 一句话 | 三栏 HUD，最像参考图 | 城市铺满屏幕，HUD 悬浮 | 平面流域图 + 仪表读数 |
| 中央是什么 | 等距城市插画 + 5 个悬浮节点 | 同一张城市图，全屏铺满 | **流域示意图**（等高线 + 河网 + 测点） |
| 雨型选择 | 左栏两张图卡（缩略图 + 考验点） | 顶部两个胶囊 | 左栏两行（名称 + 考验点） |
| 分配器位置 | 右栏整列，行高舒适 | 右侧悬浮卡，行高更紧 | 右栏并入仪表盘（表格化） |

## 2. 三版都必须满足的硬约束（已逐条自检）

- **五个场景始终存在**：投入 0 点时显示「无投入 / 0」，不隐藏、不置灰删除
- **固定水路**：学校→公园、集市→居民区、两路→车站；线宽 = 该场景 `outflow`（径流量）
- **5 点规则**：每场景 0–5 整数，总量恰好 5 才能点「开始推演」；非法时给具体原因，不只禁用
- **前端不算分**：组件只读 `store.preview`（引擎结果对象），组件内无任何评分/风险/联动计算
- **图像全本地**：`public/assets/scenes/*.svg`，无外链、无破图、无 emoji 顶替图标

## 3. 我的建议

- **如果要稳拿「功能完成度 + 视觉辨识度」双分**：选 **A**。信息一眼可读，评委不用教；后续接结算页也最容易对齐参考图。
- **如果想让评审在演示第 1 秒「哇」一下**：选 **B**。代价是底图必须继续打磨（当前等距城市是程序化占位，放大后细节经不起推敲）。
- **如果评分更看「可解释 / 工程感」**：选 **C**。它把「来水 / 净安全 / 相对基准 Δ / 联动阈值」摆在一屏，最像能论证策略的工具。

**折中方案（推荐落地路线）**：以 **A** 为主界面（截图、演示主流程），把 **C 的仪表盘细节**（Δ 列、联动阈值列表）作为「场景详情抽屉 / 结算页」复用；B 保留为可选「沉浸模式」入口。

## 4. 三版共同的已知缺口

1. **推演过程页 / 结算页未接入**：主按钮打开的是「预演摘要」弹窗，并明确标注「完整结算页在下一阶段接入」，不做假跳转、不伪造结果。
2. **预览引擎是近似**：规则版本 `rain-five-v1-preview`，与后端 `POST /api/simulations/run` 字段 1:1；接口就绪后只换数据源，组件与类型不动。
3. **雨型缩略图偏暗**（62px 卡片内辨识度不足），下一轮提高窗光密度与地面反射亮度。
4. **B 版底部趋势图偏矮**：悬浮舱高度受 1366×768 约束，图高仅 62px，曲线可读但不够舒展；下一轮把「五环」收成 3 环 + 更大的图，或把趋势图挪到右侧卡底部。
5. **五场景底图仍是程序化占位插画**（统一风格、可复现、可替换）：正式美术只需替换同名文件，布局与节点坐标不用改。

## 5. 评审用的验收证据

```text
vue-tsc --noEmit        → 0 error
vite build              → ✓ built in 5.21s（仅 chunk>500kB 提示）
截图（1440×900）        → docs/screenshots/a-1440.png / b-1440.png / c-1440.png
截图（1366×768）        → docs/screenshots/a-1366.png / b-1366.png / c-1366.png
```

自检结论：三版在 1366×768 与 1440×900 下均无横向滚动、无文字截断、无面板重叠；五场景与全部图像资产均成功加载。
