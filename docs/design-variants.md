# 设计版本对比与选择建议 v1.0

**用途**：主界面（城市规划页）三个设计方向的取舍依据。三版共用同一套设计 token、同一份 Pinia state、同一个预览引擎，只更换**信息架构与视觉组织方式**。

**查看方式**：`cd frontend && npm run dev` 后打开 `http://localhost:5199/`，左下角 `DESIGN REVIEW` 胶囊切换 A/B/C（或 URL `?v=a|b|c`，键盘 1/2/3）。
截图见 `docs/shots/variant-{a,b,c}-1440.png`。

---

## 一句话差异

| 版本 | 定位 | 中央舞台 | HUD 组织 | 适合的评审口径 |
|---|---|---|---|---|
| **A 雨夜指挥台** | 参考图直译版 | 等距城市插画（三栏中间） | 顶栏 + 左 306 / 中自适应 / 右 358 / 底 196 的固定栅格 | 「像个下雨的城市规划游戏」最直接成立 |
| **B 沉浸全景** | 沉浸版 | 城市铺满整个视口 | 悬浮四角：顶栏、右分配卡、底部舱 | 演示第一眼最抓人，空间叙事最强 |
| **C 水文仪** | 专业版 | 平面流域示意图（等高线 + 河道 + 输水管线） | 左情境 / 中示意图 / 右读数面板 / 底分项条 | 「规则可解释、指标可读」最占优 |

## 逐项对比

| 维度 | A | B | C |
|---|---|---|---|
| 城市沉浸感 | 中（三栏压缩了舞台） | **高** | 低（改平面制图） |
| 信息密度 | **高** | 中 | **高**（读数最全） |
| 五场景识别度 | 高（图标 + 名称牌 + 灯条） | **高**（更大节点） | 中（测点圆盘 + 标签） |
| 上下游关系表达 | 小图 + 画布虚线 | 画布弧线（线宽 = 径流） | **强**（管线 + 径流量标注 + 汇流环） |
| 1366×768 余量 | 中栏约 700px，够用 | 最宽松 | 右栏 344px 偏紧，需盯字 |
| 实现风险 | 低 | 中（层叠/遮挡需调） | 中（示意图几何要自己算） |
| 与「后台模板味」的距离 | 中（栅格最像后台，靠美术拉开） | **远** | 中（靠制图感拉开） |

## 建议

- **若目标是「第一眼惊艳 + 演示冲击力」→ 选 B**，把 A 的三栏信息补进 B 的悬浮卡里（B 目前分配卡信息略薄）。
- **若目标是「稳妥可交付 + 接近已确认参考图」→ 选 A**，它把五场景、5 点分配、预期指标、CTA 四件事放得最清楚，评委一眼能找到所有要点。
- **若目标是「规则可解释性」加分（这是赛事明写维度）→ 选 C**，只有 C 把「径流量 → 下游 → 车站压力」这条因果链画成了可读数。
- **我的推荐：B 作主界面 + C 的右侧读数面板借一块过来**（把 C 的风险四宫格塞进 B 的分配卡下方）。这样沉浸感与可解释性兼得，且不需要改数据结构。

## 三版共同守住的红线（评审可直接抽查）

1. 五个场景在任何分配下都存在且可见；0 点投入显示「无投入」，不隐藏、不置灰删除。
2. 固定水路：学校→公园、集市→居民区、两路→车站；没有随机连线，方向未变。
3. 资源总量固定 5 点，每场景 0–5，未分完时按钮禁用**且给出具体原因文案**。
4. 组件内不计算任何分数 / 风险 / 联动 / 策略标签，全部读 `store.preview`（预览引擎结果对象）。
5. 图表 series 全部来自 `result.forecast`，无硬编码展示数值。
6. 五张场景图 + 城市全景 + 两张雨型图全部为本地 SVG，无外链、无破图。
